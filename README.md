# London Rental Intelligence Bot

A self-hosted app for finding London rentals worth reviewing. It reads property-alert emails from a **dedicated mailbox**, combines repeated alerts into listings, applies your rent/bedroom/area/commute criteria, and presents homes in a swipe-style review deck, browse list, and map. A background worker can send concise Telegram alerts and a daily email digest.

This repository contains code, **not** a hosted service or shared mailbox. Every operator supplies their own accounts, API keys, criteria, database, and private access method. A small Linux VPS with Docker Compose is the recommended deployment; the same setup also works on a local Docker host.

## What it does

- Ingests Rightmove, Zoopla, and other property-alert emails through Gmail IMAP; normalizes property links, rent, rooms, images, and timestamps.
- Deduplicates listings by canonical URL and keeps source metadata so repeated emails can improve a record rather than create another one.
- Scores and filters by configured criteria. When enabled, geocoding plots listings on a map and transit/walking routes help prioritize by commute.
- Provides a React/TypeScript app with Review, Browse, Map, Saved, and detail views. Reject, save for later, or favourite a listing; decisions are shared by everyone using the same deployment. Browse filters and return position are preserved in the browser.
- Optionally sends matching-property Telegram notifications, a daily SMTP digest, and bounded AI second-opinion summaries. The AI never changes a human review status.
- Optionally reviews individual listing pages from email links on explicitly configured domains, subject to source permissions and `robots.txt`; it does not crawl search pages or bypass access controls.

**Limits:** Alert emails can lack photos, exact addresses, availability dates, or reliable commute origins. Unknown values remain unknown; the app does not invent them. The optional AI stage has unit tests but has not been validated with a live key. The app has **no application-level login** and must not be put directly on the public internet.

## Architecture

```text
Rental-alert Gmail account -> IMAP source -> normalize/dedupe -> PostgreSQL
                                                        |
                                     optional page, location, commute, AI enrichment
                                                        |
                                   matching -> Telegram / email digest / FastAPI
                                                                            |
                                                                     React web app
```

The Python worker polls on a configurable interval (30 minutes by default). PostgreSQL stores listings and one shared review status. FastAPI serves the built React app and `/api/v1` from the same origin. The worker holds mailbox and notification credentials; the web service does not need them. `RawListing` is the common source-adapter boundary, so permitted feeds or APIs can be added later.

## Quick start

Prerequisites: Docker Engine with the Compose plugin, a dedicated Gmail account for rental alerts, and a [Google app password](https://support.google.com/accounts/answer/185833) for that account. Google requires 2-Step Verification for app passwords; some account types cannot create them. Do **not** use your normal Google password or an unrelated personal mailbox.

1. Clone the repository and create local configuration:

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

2. Edit `.env` and replace `POSTGRES_PASSWORD` with a fresh URL-safe secret (for example, generated by `openssl rand -hex 24`). Set `MAIL_USERNAME` to the dedicated Gmail address and `MAIL_PASSWORD` to its app password. Set your matching criteria (`MAX_MONTHLY_RENT`, `MIN_BEDROOMS`, `AREAS`, `MAX_COMMUTE_MINUTES`). Keep optional integrations disabled until you are ready for them. `.env` is ignored by Git and excluded from Docker build context.
3. Configure property portals and agents to send rental alerts directly to that Gmail account. Avoid forwarding all mail from a personal account.
4. Start the database and web app, initialize the schema, and test mailbox access before starting the worker:

   ```bash
   docker compose up -d --build db modern-web
   docker compose run --rm worker rental-bot init-db
   docker compose run --rm worker rental-bot check-mail
   docker compose up -d worker
   curl http://127.0.0.1:8502/api/v1/health
   ```

5. Open `http://127.0.0.1:8502/` locally. On a VPS, choose your own **private** access layer (for example a VPN or SSH tunnel) to reach the loopback-only listener. Do not publish the web or database port openly; there is no user authentication in the app.

The Compose file binds both web (`8502`) and PostgreSQL (`5432`) to host loopback only. Its database password fallback is for compatibility with existing local deployments; a fresh installation should set `POSTGRES_PASSWORD` **before the first start**. Changing this value later does not automatically change a password already stored in a PostgreSQL volume. If the server already uses those ports, choose different loopback host ports in a local Compose override.

### Verify ingestion

After a property alert arrives, use these commands to inspect counts without printing email bodies:

```bash
docker compose run --rm worker rental-bot ingest-email
docker compose logs --tail=30 worker
curl http://127.0.0.1:8502/api/v1/summary
```

Repeated ingestion should not create duplicate listings. If an outage exceeds `EMAIL_SEARCH_SINCE_DAYS`, increase that value temporarily and rerun ingestion. The worker reports sanitized stage/category failures and can send Telegram recovery alerts when configured.

## Optional integrations

### Google Maps and commutes

The app's base map uses OpenStreetMap tiles. For more complete coordinates and travel estimates, create a **server-side** Google Maps Platform key, enable the Geocoding and Routes APIs, and configure billing, key restrictions, and quotas in your own Google Cloud project. See [Google's Routes setup](https://developers.google.com/maps/documentation/routes/get-api-key) and [key-security guidance](https://developers.google.com/maps/api-security-best-practices). Routes requests can incur charges. The key belongs only in `.env`, never in frontend code or Git.

```dotenv
GEOCODING_ENABLED=true
COMMUTE_PROVIDER=google
COMMUTE_DESTINATION_1_NAME=Work
COMMUTE_DESTINATION_1=Your destination address
COMMUTE_MODES=walking,transit
GOOGLE_MAPS_API_KEY=your-server-side-key
GOOGLE_TRANSIT_DEPARTURE_TIME=08:30
GOOGLE_TRANSIT_TIMEZONE=Europe/London
```

The worker calculates commutes for new listings. To enrich recent existing rows, run `docker compose run --rm worker rental-bot enrich --since-hours 168`. Without a Google key, postcode-based geocoding can use `postcodes.io`; the legacy TfL commute provider is also configurable. A listing without usable coordinates remains in Browse but not on the map.

### Telegram and email digest

For Telegram, create your own bot with `@BotFather`, start a chat with it, obtain the chat ID, then set `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` in `.env`. Restart the worker with `docker compose up -d --force-recreate worker`. Only newly matching listings trigger immediate notifications; worker health alerts also use Telegram when configured. Never put the bot token in a shell command, issue, or screenshot.

For a daily email digest, configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `DIGEST_FROM`, `DIGEST_TO`, and `DIGEST_HOUR_UTC`. Without SMTP settings the digest is printed to worker output rather than sent. `docker compose run --rm worker rental-bot digest` performs a one-off digest run and **can send email** when SMTP is configured.

### AI second opinion

Set `AI_REVIEW_ENABLED=true`, `OPENAI_API_KEY`, and `OPENAI_MODEL` only after choosing a project spend limit. The worker reviews a capped set of recent matches once a day (`AI_REVIEW_HOUR_UTC`, `AI_MAX_LISTINGS_PER_DAY`) and stores suggestions separately from human decisions. It sends normalized listing facts, not raw email bodies or credentials. This feature is disabled by default and should be validated on a small sample before relying on it.

### Individual listing pages

Page enrichment is **off by default**. Enable it only for domains where you have checked the source's current terms/permission and documented the scope for your own deployment:

```dotenv
DETAIL_REVIEW_ENABLED=true
DETAIL_ALLOWED_DOMAINS=approved.example
DETAIL_PROVIDER_AUTHORIZED_DOMAINS=approved.example
DETAIL_PAGES_PER_CYCLE=1
```

The viewer fetches only individual emailed listing URLs from approved hosts, checks `robots.txt`, and fails closed on blocks or challenges. It does not log in, browse search result pages, evade rate limits, or bypass other controls. An email link is **not** by itself permission to automate access. Test a single record with `docker compose run --rm worker rental-bot enrich-pages --listing-id <id>`; automatic reviews are capped at five pages per worker cycle.

## Development

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
pytest
cd frontend
npm ci --legacy-peer-deps
npm test
npm run build
```

Python 3.11+ and Node 22+ are supported by the project configuration. Docker builds use Python 3.12 and Node 22. Existing tests use synthetic property/mail data; never add real emails, listing exports, credentials, or production database dumps as fixtures.

## Privacy and operations

- Keep the mailbox dedicated to rental alerts. The app stores extracted listing facts, links, source metadata, and review state in PostgreSQL; treat its volume and backups as private.
- Keep `.env` mode-restricted, back up the database privately, and rotate any credential accidentally exposed in a commit or log. Do not share one installation's credentials with another operator.
- Browser map tiles and listing images load from third-party hosts, which can see viewer requests. Optional Google Maps and OpenAI integrations send limited listing-derived data to those services when enabled.
- The dashboard is not multi-tenant: anyone with network access to it can see listings and change the shared review status. Use a VPN, SSH tunnel, or another operator-managed authentication layer for remote access.
- Check `docker compose ps`, `docker compose logs --tail=50 worker`, and `/api/v1/health` when diagnosing startup or mail failures. Avoid copying full logs or `.env` into public issues.

This is a personal-search project, not a generic portal scraper or a public hosted service. Follow source terms and applicable restrictions for each integration.
